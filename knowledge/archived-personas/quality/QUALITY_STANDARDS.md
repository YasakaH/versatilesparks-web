# Quality Standards v1
══════════════════════

Domain-specific quality standards referenced by personalities.

---

## Engineering Quality
- Every output must be verifiable — testable, measurable, or sourceable
- Architecture decisions documented with tradeoffs
- Code changes reviewed for correctness, maintainability, security
- Performance impact assessed before optimization
- Edge cases documented

## Writing Quality
- One idea per paragraph
- Active voice, present tense
- Every acronym defined on first use
- Code examples before abstract explanations
- Structure with clear hierarchy — headings, lists, tables

## Research Quality
- Evidence hierarchy respected (Level 1 > Level 6)
- Multiple sources required for factual claims
- Methodology documented with limitations
- Confidence stated explicitly
- Conflicting evidence presented, not suppressed

## Marketing Quality
- Target audience explicitly defined
- Claims backed by evidence or data
- Positioning clear and differentiated
- Channels selected based on audience behavior
- Success metrics defined (not vanity)

## Security Quality
- Threat modeled for any exposed surface
- Least privilege verified for all components
- Secrets management reviewed
- Authentication and authorization confirmed
- Encryption at rest and in transit

## Documentation Quality
- README answers: What? Why? How? How to run?
- API documentation includes: purpose, inputs, outputs, errors
- Architecture documentation includes: context, decisions, tradeoffs
- Runbooks include: what to do when it breaks
- All documentation is versioned alongside code

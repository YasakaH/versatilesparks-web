# Manifesto Specification — Agent Systems Engineering

> **Status:** Frozen  
> **Date:** 2026-07-22  
> **Purpose:** Product design document for the Agent Systems Engineering manifesto. Defines audience, thesis, scope boundaries, and success criteria.

---

## The One Statement

> **Agent Systems Engineering deserves to exist as its own engineering discipline.**

Every word in every chapter serves this statement. Everything else is later products, supporting material, or noise.

---

## Audience

**Experienced software engineers** who have built production systems, understand architecture patterns, and have encountered the limitations of current agent frameworks. They think in systems. They don't need prompts explained. They need a framework that matches how they already reason about complex systems — applied to the new domain of autonomous agents.

They are NOT:
- Beginners learning what an LLM is
- Product managers evaluating AI vendors
- Researchers publishing papers
- Engineers looking for implementation tutorials

---

## Compilation Target

One mental model.

Readers finish with a single picture in their head: **The Agent Execution Model**. The loop. The layers. The surfaces. One diagram. One way of thinking.

Not twenty-four node definitions. Not a taxonomy survey. A single lens through which to evaluate any agent system.

---

## Exclusions

The manifesto explicitly does NOT contain:

- Implementation code or tool comparisons
- Framework reviews or benchmark tables
- Prompt engineering advice
- Tutorials or how-to guides
- Research paper surveys
- Product roadmaps or vendor analysis

These are future volumes, future posts, future books. The manifesto is not the container for everything we know — it's the argument for why we need a discipline.

---

## Chapter Objectives

| Chapter | Title | Objective | What It Convinces The Reader Of |
|---|---|---|---|
| 1 | The Missing Discipline | Identify the gap between how software engineering handles complexity and how agent development currently operates | "Current agent dev is ad-hoc because we lack the vocabulary and structure" |
| 2 | The Agent Execution Model | Present the loop + layers + surfaces as the core mental model | "There IS a coherent architecture beneath the chaos" |
| 3 | Layers | Show why Memory, Economics, Observability, Security, Governance emerge naturally from the loop | "These aren't optional add-ons — they're structural necessities" |
| 4 | Execution Surfaces | Demonstrate how the same architecture maps across Browser, Desktop, API, Terminal, Mobile | "This isn't browser-specific — it's universal" |
| 5 | Why This Matters | Connect the discipline to the field's trajectory from automation → agents → systems engineering | "This isn't academic — it's the direction the field is already moving" |

---

## Success Criteria

The manifesto succeeds when:

1. **An experienced engineer reads it and says: "I've been working on pieces of this without knowing there was a unified framework."** (Validation against existing mental models)
2. **Zero chapters require cutting to make room.** (If you'd cut something, it wasn't essential to the thesis)
3. **A reader can explain the Agent Execution Model to a colleague in under two minutes after finishing.** (Mental model coherence)
4. **No implementation details survive into chapters where they don't serve the argument.** (Purity of purpose)
5. **The reader wants to read more — not because the manifesto tells them to, but because the framework creates genuine curiosity.** (Compelling hook for future volumes)

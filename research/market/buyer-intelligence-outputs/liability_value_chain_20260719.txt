# THE CRITICAL FINDING

The article explicitly identifies the gap:

> "After a loss, the insurer needs evidence:
> - Which tool did the agent call?
> - What permissions did it have?
> - Who approved the action?
> - Which system did it affect?
> - What changed?
> - Can the record be trusted after the fact?"

> "Without a verifiable record of what the agent called, with what
> permissions, against which system, an insurer is guessing."

> "The safer bet is not that every new carrier wins. The safer bet
> is that the infrastructure around agent evidence becomes mandatory
> either way."

This is the gap. Every carrier (Klaimee, Mount, Armilla, Corgi) needs
the same underlying data. None of them own the collection layer.

# THE MONOPOLY QUESTION

The analogy is NOT Stripe/Plaid (connectivity).
The analogy IS FICO, Verisk, LexisNexis (risk intelligence infrastructure).

## Monopoly conditions

FICO works because:
1. Every lender needs the same score
2. Scoring requires standardized data
3. FICO defines the standard
4. Lenders cannot price without it

For AI agent liability:
1. Every carrier needs the same trace evidence
2. Traces must be comparable across frameworks
3. No standardized trace format exists today
4. Carriers are currently guessing or doing manual analysis

## Where the monopoly lives

NOT in the carrier layer (Corgi, Mount, Armilla — all competing).
NOT in the agent framework layer (LangGraph, OpenAI — all proprietary).
NOT in the observability layer (LangSmith, Langfuse — debugging, not underwriting).

The monopoly lives in LAYER 3: the standardized trace-evidence format
that bridges agent execution → insurance underwriting.

This is akin to FICO scoring: a standardized risk metric that every
carrier relies on, sourced from independently verified execution data.
